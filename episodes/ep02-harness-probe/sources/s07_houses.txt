還有一個不在公式裡、但從四欄對照裡冒出來的東西。Opus 一回合（帶事後知識）的版本，跟 Claude Code 六迭代的版本，對人眼來說差距不大。Claude Code 那 15 萬 token 買到的東西，有一大半是「知道哪裡會壞」，而那個知識一旦寫成 notes，只要幾百個 token 就能帶給下一個模型。

harness 的產出不只是成品，是失敗清單。失敗清單比成品值錢。

這就是 Felix 那句「先接好 crash report」的另一種說法。crash report 不是工具，是前一次失敗的記錄。接好它，等於讓下一次迭代從第 1 版之後開始。

09 · 三種屋子

鏡子篇說過兩種人、兩套用法。這次改成三隻小豬，因為大野狼是真的：鋸齒邊界每幾週就移動一次，撞到了才知道屋子夠不夠。

 | 
 | 屋子 | 是什麼 | 能做到 | 大野狼來的時候

 | 稻草屋 | 聊天介面，人當眼睛 | 第 1 版，能跑、沒截斷、看起來沒錯 | 每一回合人要等很久；人眼看不到第 40 秒；缺陷全在模型自己加的範圍

 | 木屋 | Max 帳號加 Claude Code，機器當眼睛 | 第 6 版，功能清單用探針驗過 | 裁判的解析度決定一切；探針要自己寫；撞週配額

 | 磚屋 | 實驗室的 harness，眼睛接在資料和機器上 | crash-free 這種結果級的目標 | 不知道，外面的人看不到；五千人的樣本，而且是被篩選過的

Felix 的「要更有野心」是對住磚屋的人講的。對住稻草屋、試過而且不滿意的人，那句話是 Bandura 四個來源裡最弱的那一種，開給一個缺的是條件的人。誠實的建議不是「想大一點」，是「先接好眼睛」。

鏡子篇結尾那段「別信這份報告，帶回去自己驗一次」，這篇等於把它做了一遍。要驗，協定在 repo 裡：三段 prompt 一字不改、裁判先於題目、人只准貼症狀。跑完把每一輪卡在哪寫下來——那份清單，會比你做出來的飛機值錢。

帶回去驗的最小版本：
1. 拿 prompts/A.md 原文，貼進你平常用的介面，一次生成。
2. 真的瀏覽器打開，看滿 60 秒。只記症狀，不記解法。
3. 把症狀原話貼回去，最多八回合。
4. 每一回合記：行數、能不能跑、你看到什麼、它改了什麼、改的是不是你沒要求的東西。
5. 跟 runs/ 裡的四欄對照。差的那一欄，就是你的屋子。
