STAGE 02 · 查核 · IS IT TRUE
「只用 three.js，沒有 3D 物件」是真的嗎
先把話說準。three.js 是一套讓瀏覽器畫 3D 的函式庫。流傳的說法是，這些遊戲除了它以外什麼都沒載入，沒有建模軟體做出來的模型檔，也沒有圖片和音效檔。
這不等於「沒有 3D 物件」。畫面上的貨櫃和機器狗仍然是 3D 模型，差別在來源。它們沒有對應的檔案，全是遊戲啟動時由程式當場算出來的：形狀由函式組出來，表面的鏽和積水由著色器算，聲音由合成器產生。這種做法叫程序化生成，在繪圖領域是幾十年的老技術。至於「即時算圖」，任何 3D 遊戲都是即時算的，不是這一波才有。
先分清楚兩條路線
洗版的作品其實走兩條路，常被混在一起講。
路線 模型寫的是 成品 代表作
Blender 操控建模軟體的 Python 腳本 一支算好的影片，不能互動 恐龍短片、Bugatti 跑車
three.js 在瀏覽器裡執行的程式 打開網頁就能玩 Saltline
兩條路的共同點是素材都由程式寫出來，沒有人動手建模。差別在算圖的時間點。Blender 那條路是事先一格一格算好，所以畫面可以很細，也需要顯示卡花時間去算。three.js 那條路才是邊玩邊算。「只用 three.js」和「即時算圖」講的是後者，恐龍屬於前者。
我自己打開來看了
Rieseberg 說，所有貼圖和模型都是函式，原始碼就在 HTML 裡，誰都可以檢查。有人在討論區提出合理的懷疑：1.4 MB 的單一檔案，從外面看不出裡面是不是藏了一大串編碼過的圖片。所以我把 GitHub 上的公開副本抓下來，用程式掃了一遍。
SPEC · SALTLINE 公開副本
檔案 單一 HTML，1,423,569 位元組
組成 一段程式。前半是 three.js 本身，後面約 48% 是遊戲和生成用的程式
內嵌圖片 0 個。也沒有任何長串的編碼資料
載入器 整個檔案沒有模型載入器。遊戲那一半也沒有呼叫圖片、貼圖或音訊的載入器
外部資源 只有頁首的 Google Fonts 字型。遊戲程式裡沒有任何網址
遊戲程式裡 一千多個函式。貼圖有 12 張，全是程式當場畫出來的。正弦函數出現三百多次，雜訊函式近兩百次
結論是這句話對 Saltline 成立。另一份獨立的檢查看的是 3.6 MB 的原始頁面，同樣沒找到模型載入器和外部模型。要說明的是，我看的是別人轉存的副本，不是原始頁面，做的也只是靜態掃描，沒有一行一行讀。
