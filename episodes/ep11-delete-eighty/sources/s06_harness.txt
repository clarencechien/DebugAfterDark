法則 05harness 變薄，不是消失
Responses API 這一年長出來的東西幾乎是照著 harness 的內臟長的：hosted shell 與 container_auto（Debian 12，受控網路）、Agent Skills（SKILL.md）、server-side compaction、內建 web search / file search / computer use / MCP。
但 OpenAI 自己的教學仍然是：呼叫模型 → 檢查 function_call → 自己執行 tool → 帶 previous_response_id 送回 → 重複。你仍然要做錯誤處理、非同步任務生命週期、成本計算、權限閘門、跨 session 狀態。發布 Astra 的同一篇裡，OpenAI 宣布「we are also updating the Codex harness」——連他們自己都還在養殼。
所以該做的是拆換，不是拆掉：自己寫的 shell 沙箱、summarize、skill loader 可以評估換成 API 內建；loop、核准、成本、狀態留在你的殼裡。harness 選型的規則只有一條——用廠商自家的，除非你需要接地端模型或多供應商。harness fit 的差距方向確定、幅度未量化（法則 10）。

歸位：專案技術事實進 CLAUDE.md 並進 git（跨機器有效、可 review diff）；跨專案的個人偏好交給 personal memory；可重複的流程寫成 skill——唯一換 harness 還在的一層。API 層沒有第一方的跨 session 記憶：compaction 是 session 內，container 隨 session 拆掉。
然後是大多數記憶系統都缺的那一層：回饋訊號。它們記「發生了什麼」，不記「結果對不對」。權重凍結下的實證：把每次 episode 蒸餾成可檢索的自然語言規則，只靠成敗訊號是 1.6× baseline，加上事後修正是 2.6×，而且那份記憶換一個模型讀依然有效。可執行版本是在你的自動化迴圈裡多存一欄「這次可不可用」，失敗時把修正寫回去。（該研究只測單一領域，對照組是靜態 RAG。）
