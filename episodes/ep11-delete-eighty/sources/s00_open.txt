序 · 什麼真的變了
三件事，其他都是雜訊
GPT-6 Astra 上線兩週，二手說法比一手文件跑得快。但把 system card、定價頁、兩家的開發者指引讀完，真正改變工程決策的只有三件事：
能力長過了鷹架。Anthropic 對 Opus 5 / Fable 5 級模型移除了 Claude Code system prompt 的 80% 以上，coding eval 沒有可測量的損失；OpenAI 對 Astra 的指引同一個方向——刪掉為上一代寫的補丁。過去兩年累積的 prompt 大部分是在補模型的短處，短處補上了，補丁還在，而且現在是負債。
看得到的推理變少了。Astra 的 CoT controllability 從 GPT-5.6 Sol 的 16.1% 跳到 60.9%，system card 直說可監控性下降。這不是「CoT 結束了」，是你不能再拿模型的文字說明當稽核紀錄。
API 吃掉了手腳，沒吃掉判斷。hosted shell、skills、compaction 都進了 Responses API，但 loop、權限、成本、跨 session 狀態還是你的。harness 變薄了，沒有消失。
十條法則就是這三件事各自的操作版本：先刪，判斷留在殼裡，把信任的邊界畫清楚。

法則 01先刪，再加
Anthropic 點名的四件事，今天就能在自己的 CLAUDE.md 上做：
刪掉互相衝突的指令。「leave documentation as appropriate」配上「DO NOT add comments」，模型得先花力氣調解你的自相矛盾。
用判斷取代規則。舊：「預設不寫註解，絕不寫多段 docstring」。新：「寫出讀起來像周圍程式碼的程式碼——比照它的註解密度、命名與慣用法」。
刪掉 tool 使用範例，改成把參數設計得更有表達力，讓模型從介面本身推斷行為。
同一條指令只放一處。不要在 system prompt、tool description、skill 三個地方重複，收斂到 tool description。
Claude Code 的 /doctor 就是拿來找這些多餘約束的。順序很重要：先跑一輪刪，再考慮加任何新東西。
