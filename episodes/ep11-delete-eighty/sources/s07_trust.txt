參 · 信任的邊界 — 監控與版本
看動作，不看解釋
法則 08把文字紀錄降級成 UX，把動作紀錄升級成稽核
那篇在時間線上傳開的 Astra 文章，敘述八成是錯的，但它最後兩條建議是對的，而且正好是 system card 支持的：
telemetry 從文字改成動作。模型的 CoT、摘要、「我剛剛做了什麼」都是給人看的介面，不是稽核紀錄。有執行權限的 agent，紀錄的是 syscall、網路請求、檔案 diff。
sandbox 預設網路關閉，按目的地逐一打開；有瀏覽器或終端權限的 agent 跑在受限容器裡。這正是 Codex CLI 與 Claude Code CLI 兩邊不約而同的設計：檔案與網路必須同時隔離，只擋一邊等於沒擋。
依據：Astra 是 OpenAI 第一個達到網安 Critical 的模型；sandbagging 偵測器在被明確指示規避的對抗設定下失效超過 89%；system card 自己的話是「若模型想暗中 sandbag，我們很可能抓不到」。自主越界的實際數字是 500 次中 2 次——所以不是恐慌，是把稽核的依據換掉。
法則 09釘住版本，養一組自己的回歸題
靜默換版是預設狀態，不是意外
一份涵蓋 16 家供應商的研究：沒有任何一家能證明「被評測的模型」等於「現在服務的模型」。DeepSeek 的 deepseek-chat 同一個 id，19 個月底下換了 10 個版本。9 家一方供應商中 8 家有 changelog，只有 1 家（Anthropic）精確指名被評測的版本，0 家能用公開資訊把部署中的模型對應回已發布的安全評測。
權重部署後是凍結的，你的使用不會讓它變聰明；但「用久了它變了」不完全是錯覺——模型確實變了，不是因為你，是因為底下被換掉了。沒有固定基準，你會把供應商換版誤判成自己改壞了，反過來也一樣。
做法：盡量使用有日期的版本識別；維護 20–50 題、覆蓋你真實任務形狀的回歸題；每次行為變化先跑它，再決定是改 prompt、關 skill 還是回報問題。法則 01 到 04 的每一次刪除，也用它驗收。
法則 10自己的 workload 才是排行榜
業界現在的共識是：一個公布的分數是「模型 × harness」這一對的屬性。poolside 直接承認 harness overfitting 是已知限制——模型在只差一點點的第三方 harness 裡會 struggle to adhere to tool schema definitions。但公開資料裡找不到同一個模型在不同 harness 下的對照實測：方向確定，幅度未知。ARC-AGI-3 上同一個 Astra，標準 harness 62.7%，Provider Adapter harness 99.9%。
