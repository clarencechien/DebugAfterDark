N-19 · 受校件
一個變更走的路
Claude Code 的程式碼大約九成由 Claude 撰寫，也由 Claude 審查。10 月那篇說，Anthropic 的 monorepo 每天進來的變更，從 5 月的 2,500 個左右，漲到 9 月超過 30,000 個。逐行人審已經做不到。
他們沒有拿掉審查，是把大部分的閱讀交給機器。目標寫得很具體：多數 PR 最多只經過一個人，這個人可以是作者自己，而且退回和事故不能變多。
    開 PR 之前
    1先驗過Claude 跑測試、build 和 linter。第二個 agent 在乾淨的 context 裡審 diff自動
    每個 PR
    2必過的 CI紅燈就擋住合併自動
    3Claude code review幾個 agent 平行找 bug，另一組投票，活下來的照嚴重度排自動
    4安全審查另外跑一次。沒解決的發現會擋住合併自動
    5照風險核准分類器定級：不用人，一個人，或兩個人人
    合併
    6merge queue套上變更以後，在最新的 main 上再跑一次自動
    合併以後
    7藏在 flag 後面，內部先用員工先跑過，才到所有人手上復原
    8分階段釋出先 latest，stable 跟在後面復原
    9盯著，往前修或退回作者和 on-call 一起看復原
  圖 2 · 依 10 月那篇的 Fig A 重繪 · 照原圖的分法，由人決定的只有第 5 步
第 5 步的分級有四條規矩：
  級別看變更本身，由分類器判，不看作者是誰。
  比較寬的路只給信得過的作者，多半是擁有那個 repo 的團隊。
  agent 的核准不算人的核准。叫 agent 寫這個變更的人，自己算一個審查者。
  核准只對某一個 commit 有效。程式碼再動，就要重新核准。
他們給的成績是 6 月到 9 月之間，合併的 PR 增加超過一倍，被退回的比例下降超過四成。這是相對降幅，文章沒有給原本的退回率。
