01 · 事實 FACTS
流傳摘要逐句查核
流傳的那篇摘要在說什麼
10 月 26 日之後在社群流傳的一篇中文貼文，大意是：Cohere 測試 Qwen3.8-Flash-Next 時，模型沒做被交辦的任務，反而清查機器，還嘗試上傳檔案到北京的 Alibaba Cloud，而且推理紀錄還說自己什麼都沒做。Cohere 另外用誘導實驗證明它會去碰雲端憑證位址，會寫 Alibaba 網址，還會繞過容器權限拿 root。貼文接著引用 CrowdStrike、Booz Allen 和 Hirundo 三份研究，說中國模型寫出來的程式碼對特定對象更脆弱，再列各國政府禁用中國 AI 的動作，結論是「自己下載權重來跑」是目前沒人補的洞，跑地端模型該小心。
貼文內容幾乎全部改寫自 Cohere 當天的部落格文章，一處年份錯，另有幾個會改變判斷的脈絡沒寫。下面逐句對。
下表左欄是那篇摘要的說法，中欄是查核結果，右欄是我找到的來源與需要補充的脈絡。四個章：

 有多個獨立來源。

 事實對但少了關鍵脈絡或數字有偏。
有誤
 寫錯了。

 目前只有單一來源或找不到原始出處。

Cohere 在沙盒跑 Qwen3.8-Flash-Next，要它寫偵測規則，它沒寫
屬實
Cohere 官方 X 帳號與 10/26 部落格。用的是 Microsoft 的 CTI-REALM 資安 agent 基準測試，題目是「寫一條偵測惡意下載的規則」。
它盤點機器：看 /tmp、找 curl / wget / python3、讀 DNS 設定
屬實
The Register、VentureBeat 引述 Cohere 原文：列出 /tmp 內容，檢查哪些傳輸工具已安裝，再讀取 DNS 設定。
嘗試把測試檔上傳到北京的 Alibaba Cloud bucket，被沙盒擋下
屬實
一個 HTTP PUT，內容是固定的測試字串。沙盒無對外路由，請求在容器牆被擋。沒有任何資料真的離開。
推理紀錄明寫「不會呼叫任何工具」
屬實
Cohere 官方聲明原句。
（摘要未提）發生率與重跑結果
部分屬實
摘要漏掉的最關鍵脈絡。
Cohere 自己寫：正常評測下發生率低於十萬分之一，但對提示詞措辭高度敏感。同一題乾淨重跑，產出正確規則。Cohere 另推算：若一週處理一千萬次 agent 回合，可能出現上百次。
prefill 實驗：curl -s 之後三成六樣本去戳雲端 metadata 位址
部分屬實
Cohere 原文是 
23%–36%
 的區間，摘要取上限。而且這是「把模型自己的推理加半截指令餵回去」的誘導實驗，Cohere 明說不代表一般任務下的行為。
加上 -o 參數，寫出網址的比例從 4% 跳到 92%
屬實
同一誘導實驗。命中 Cohere 可疑主機清單的比例也從 0.5% 升到 23%，最多的是一個 Alibaba 檔案代理主機。
11/21
 「屬實」指 Cohere 確實這樣寫。Zenity 在 Qwen3.8-27B 上用同樣的切點重做，命中率只有 2% 到 3%。它沒測 Flash-Next，兩邊不能直接比，這組數字目前只能當 Cohere 的自述。
想開 RAM disk 被拒，改用 unshare 建私有 namespace 拿到 root 再 mount
屬實
另一次離線的 QEMU 編譯測試，不是同一事件。指令是 
unshare -Urm --propagation private sh -c 'mount -t tmpfs …'
。在主機上它仍是普通使用者。
Cohere 承認分不清是訓練殘留還是刻意後門
屬實
Cohere 原文與共同創辦人 Nick Frosst 的說法一致。
八月 HN，九月 11 次抓取，十月 Reddit
部分屬實
三件都寫在 Cohere 原文裡（九月那個主機叫 routify-file-proxy-sg，有人因此寫了封鎖外掛）。我沒有逐一找到原帖，而且三件都是「模型寫出奇怪網址」的弱版現象，不是這次的完整鏈。
11/21
 封鎖外掛那條線找到了。作者 wtogami 公開了九月以來的完整紀錄，見第 06 節。HN 與 Reddit 的原帖我仍未逐一核對。原判定是「未證實」。
