  最上層分成 electron/main 和 electron/renderer 兩個目錄，用相依圖分析和 lint 擋住互相匯入。這是 Cursor 時期學到的：agent 常把主程序的程式拉進畫面那邊，造成卡頓。
  Cursor 時期，agent 很愛拿計時器修問題，每個計時器旁邊都寫一段註解說明為什麼，結果計時器到處都是。Grok Bot 乾脆禁掉約 99% 的註解，因為註解會過時，也沒辦法強制。改成 lint 規則，錯誤訊息直接叫 agent 去修根本原因。
驗證。每一次糾正都變成一條確定性的檢查，審查要看的東西就越來越少。她說程式審查已經縮成看驗證產出，例如影片和截圖，還有形式化驗證的結果。他們用 TLA+ 檢查跨裝置的通知流程，用 Lean 檢查自己寫的 virtualization 程式庫會不會閃爍或抖動，用 Bombadil 做 UI 的 property-based testing。她說在 X 上看到 Cindy 的貼文：Cindy 原本不信任 agent，六個月後說自己每天 70% 的 token 花在驗證上。她說自己也差不多。逐字稿只有名字，有一份整理說這位是 @copyconstruct。這些技術都不新，以前是寫起來和維護起來都太貴。接回上篇 N-02
成果。團隊上個月上線約 11,000 個 PR，大約每天出一個穩定版。10 月有約 227 人貢獻過至少一個 PR，包括偶爾來一次的人。退回率穩定在 0.5% 左右。啟動和打字都比上市時快，開對話和切對話也是。她也承認 Electron 有它的天花板。
收尾。每次糾正 agent，先從改程式庫下手。先加 lint 擋住新的反模式，再清掉舊的，再把驗證做紮實。內圈還在產 slop 的話，自動化外圈只會產出更多 slop，還燒掉很貴的 token。地基打好之後，Grok Bot 現在每次發版都會自動開一個專案，像真的使用者一樣把整個 app 跑一遍，找到 bug 就開修正 PR，然後自動合併。她說大部分產品程式碼現在不經過深度的人工審查就進去了。
