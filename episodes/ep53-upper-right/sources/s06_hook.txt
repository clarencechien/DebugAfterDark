報告 QA：「hook 就是我的安全機制？」體感：寫了 PreToolUse 擋 rm -rf，安全了。文件：官方講得很直白：hook 的過濾是 best-effort，解析失敗時會 fail open（放行），強制 allow 或 deny 要用 permission 系統，hook 管的是流程紀律。另外還有三個必踩的坑。exit code 1 是 Unix 的失敗慣例，但 Claude Code 把它當成不阻擋的錯誤照做，要擋只有 exit 2。PostToolUse 擋不住任何事，因為工具已經跑完了。Stop hook 連擋 8 次之後會被覆蓋、直接結束，它是強力推一把，算不上絕對的閘門。分工可以這樣記：permission 管安全，hook 管紀律，CLAUDE.md 管建議。
名詞：hook 是在生命週期特定時點自動執行的 shell 指令。exit 2 會阻擋並把 stderr 餵回模型，exit 1 不會擋（最大的坑）。
